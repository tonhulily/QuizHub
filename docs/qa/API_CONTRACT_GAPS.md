# Đối chiếu API client với OpenAPI

## Nguồn và phạm vi

Swagger UI công khai được đọc bằng GET qua TLS ngày 21/10/2026. UI tải initializer/config rồi chỉ định spec tại [OpenAPI JSON](https://snsqb.duckdns.org/api/v1/docs/openapi.json). Snapshot OpenAPI 3.1.0 có 128 paths, tiêu đề “Hệ Thống Mạng Xã Hội Học Tập & Ngân Hàng Đề Thi - SQB HUST”. Hash SHA-256 `63dc2323f2a0b07a8ba09f8623c7612c8e2f0af327a4c91888632f5943939cc5`, 317,935 byte; retrieval timestamp `2026-10-21T16:32:59+00:00`. File `qa-artifacts/swagger/openapi.json` và `metadata.json` bị ignore nên không thuộc commit. Lỗi DNS trước đó xảy ra trong sandbox; lượt đọc có quyền mạng sau đó thành công.

Đã đối chiếu 41 request template với snapshot: 41/41 method/path khớp 33 OpenAPI operations; không có query parameter, JSON property hoặc multipart field nào ngoài schema. Các request bodies đã parse với fixture thay thế; enum đang dùng đều nằm trong enum schema. Đây là đối chiếu tĩnh OpenAPI và mã client, không chứng minh service runtime khớp tài liệu.

Collection chỉ gồm endpoint các repository hiện gọi. Spec có thêm endpoint chưa được gọi trong phạm vi này, chẳng hạn `PUT /comments/{commentId}`, `GET /follows/followers`, `GET /follows/following`, `DELETE /users/me`; không đưa các endpoint đó vào toolkit như thể app đã tích hợp.

## Kết quả theo module

| Module | Đối chiếu request và schema | Status HTTP được liệt kê trong OpenAPI |
|---|---|---|
| Auth | `POST /auth/login` đủ email/password/device_id/platform và device fields tùy chọn; spec có thêm `fid` tùy chọn app không gửi. Refresh body `refresh_token`; logout không body; change-password có old/new password. `platform` enum: `IOS`, `ANDROID`, `DESKTOP`, `WEB`. | Login 200/400/403; refresh 200/401/403; logout 200/401; đổi mật khẩu 200/400/401. |
| User/profile | GET me, PUT me và GET user ID đều có trong spec. Update fields khớp; gender `MALE|FEMALE`, ngày sinh `date`. | GET me 200/401/403; PUT me 200/400/403; GET user 200/403/404. |
| Posts | Create body field/type/enum khớp (`content`, `media_urls`, `visibility`, `post_type`, tùy chọn `subject_id`). Get, user posts, my posts, update và delete có method/path tương ứng. | Create 200/400/401/403/404; GET post 200/401/403/404; update 200/400/401/403/404; delete 200/401/403/404; my posts 200/401; user posts 200/401/403. |
| Comments | List query names/sort enum, create target/content fields và delete route khớp schema. `target_type` enum `POST|SESSION|QUESTION`. | List/create 200/400/401/404; delete 200/401/403/404. |
| Relations | Request/accept/decline JSON fields khớp. Friendship/follow/block path IDs là integer; `DELETE /friendships/{friendId}` mô tả ID người bạn, khớp `userId` mà app caller truyền. | Friend/request lists 200/401; send 200/400/401/403/404/409; accept 200/401/403/404; decline 200/401/403/404; unfriend 200/401/404; follow POST 200/400/401/403/404, DELETE 200/401/404; block POST 200/400/401/404/409, DELETE 200/401/404. |
| Feed/search | Query names khớp. Search `after` là integer offset và repository cũng dùng `int?`. | Feed 200/401; search 200. |
| Media | Multipart field `file` và query `purpose` khớp; purpose enum `AVATAR`, `COVER`, `QUESTION`, `POST`, `COMMENT`, `CHAT`, `DOCUMENT`. | Upload 200/400/413/500. |
| Reaction/report | Required body fields và enum schema đang dùng khớp; app chỉ gửi reaction LIKE. Report body yêu cầu target, violation. | React 200/400/401/404; report 201/400/404. |

Các status ở bảng là status **được tài liệu khai báo**, không phải status đã quan sát. OpenAPI gói response bằng `{code,message,data}`; `code` chỉ có type string, không có enum/giá trị cụ thể. Response schemas khai báo envelope và data; app cũng unwrap envelope tại `api_client.dart:272-285`. Không dùng các status này để khẳng định status/error body thực tế khi chưa gửi request được phép tới backend test.

## Chênh lệch cần owner xác nhận

1. **Kiểu `after` phân trang:** OpenAPI khai báo query `after` là integer và `CursorPaginationDto.after` cũng integer; mô tả spec gọi đó là ID hoặc timestamp tùy endpoint. `CursorPage.after` lại là `String?`, đọc qua `J.asString`; repository post/comment/friend/feed nhận `String?`, trong khi search nhận `int?`. Nguồn client: [cursor_page.dart:10](../../lib/data/models/cursor_page.dart#L10), [comment_repository.dart:18](../../lib/data/repositories/comment_repository.dart#L18), [post_repository.dart:84](../../lib/data/repositories/post_repository.dart#L84), [friend_repository.dart:21](../../lib/data/repositories/friend_repository.dart#L21), [feed_repository.dart:31](../../lib/data/repositories/feed_repository.dart#L31), [user_search_repository.dart:27](../../lib/data/repositories/user_search_repository.dart#L27). Spec pointers: `/components/schemas/CursorPaginationDto/properties/after`, `/paths/~1comments/get/parameters`, `/paths/~1activity-feeds/get/parameters`, `/paths/~1friendships/get/parameters`, `/paths/~1posts~1me/get/parameters`, `/paths/~1users~1{userId}~1posts/get/parameters`, `/paths/~1search/get/parameters`. `J.asString` chuyển integer response thành chuỗi và query HTTP vốn gửi text; giá trị chữ số có thể tương thích. Hợp đồng không mô tả opaque cursor; toolkit yêu cầu nhập giá trị số. Cần xác minh response thực/owner trước khi coi đây là lỗi app.
2. **Visibility bắt buộc ở PUT post:** schema `UpdatePostRequest.required` có `visibility`, còn `PostRepository.update` bỏ key này nếu caller không truyền. Source: [post_repository.dart:43](../../lib/data/repositories/post_repository.dart#L43). Spec pointer: `/paths/~1posts~1{id}/put/requestBody/content/application~1json/schema/required` (schema `$ref` tới `UpdatePostRequest`). Request Postman được đánh dấu repository-only; body theo spec phải có `visibility`. Đây là khác biệt giữa method client và schema; chưa xác minh backend có cho phép update content/media mà thiếu visibility hay không.
3. **Riêng tư profile:** `ProfileResponse` trong spec có cả `email` và `date_of_birth`, cùng schema được dùng cho GET me và GET `/users/{userId}`: `/components/schemas/ProfileResponse/properties/email`, `/components/schemas/ProfileResponse/properties/date_of_birth`, `/paths/~1users~1{userId}/get/responses/200`. README dự án lại ghi GET `/users/{id}` không trả hai field (`README.md:60`); ProfileModel parse cả hai (`profile_model.dart:71-137`). Schema chung không nói field có luôn được trả hay được lọc theo người xem. Cần owner chốt chính sách/response thực tế; collection không kết luận lộ dữ liệu và không assert email/ngày sinh.
4. **Mô tả enum trong spec không đồng nhất với enum schema:** `ReactRequest.target_type` prose nhắc COMMENT nhưng `enum` chỉ gồm POST/SESSION/QUESTION; app enum cũng không gồm COMMENT. `CreateReportRequestDto.violation_type` prose nhắc HATE_SPEECH và INAPPROPRIATE_CONTENT, nhưng enum thực là HARASSMENT/HATE_STATEMENT/SPAM/OTHER; `ReportRepository` gửi các giá trị enum này. Dùng enum schema làm căn cứ cho template, nhờ API owner chỉnh prose. `UpdateProfileRequest.gender` lặp MALE/FEMALE trong enum array nhưng tập giá trị vẫn giống app.
5. **Giá trị code/error:** schema envelope khai báo `code` string nhưng không enum hóa mã thành công/lỗi. Client chấp nhận `0000`, `1000`, `200` và chuỗi chỉ gồm số 0 (`response_codes.dart:8-41`); đây là client policy, không được chứng minh bởi OpenAPI snapshot. Các status HTTP trong bảng không xác định ánh xạ `code`, message hay error data thực tế.
